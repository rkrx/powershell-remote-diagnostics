# Reverse Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Windows RC/client packages with an integrated TLS reverse relay and one authenticated diagnostic client per RC.

**Architecture:** Keep diagnostic TLS end to end. A separately authenticated gRPC relay control stream owns a bound public TCP listener and pairs accepted sockets with RC-initiated bidirectional data streams. A diagnostic session stream grants exclusive admission, with heartbeat expiry independent of PowerShell work.

**Tech Stack:** .NET 10, existing gRPC/protobuf libraries, ASP.NET Core Kestrel, PowerShell SDK 7.6.8, existing MCP/Avalonia client, xUnit.

**Spec:** `docs/superpowers/specs/2026-10-31-relay-design.md` (approved by owner).

## Global Constraints

- Windows x64 client/server release builds only; keep macOS source development, no Linux distribution.
- Server executable `powershell-rc.exe`; relay mode shares the server package but never initializes PowerShell.
- Relay control port 8080, public inclusive range 20000–25000, bind All, advertised hostname defaults to machine hostname.
- At most 100 registrations and 8 tunnels per registration; data frames at most 32 KiB; tunnel setup timeout 10 seconds.
- Heartbeats every 5 seconds; diagnostic session and RC registration expire after 20 seconds without liveness traffic.
- A port belongs to the RC registration until RC disconnect/shutdown/expiry; a client disconnect preserves port and URL.
- All public docs/messages English and generic; no secrets in connection logs, no script replay or implicit execution cancellation.
- Prefer supported .NET packaging; do not introduce a custom native bootstrapper. Report any physical engine layout limitation.

## Review Focus

- Network partitions and delayed cleanup must never release a replacement session or forward an old allocation into a reused port (Tasks 2–3).
- A slow/no-handshake external socket must not block authenticated clients indefinitely or consume unbounded tasks/buffers (Task 3).
- Failed client setup, including cancelled GetInfo, must release its admission slot without logging credentials (Task 2).
- Half-closed TCP streams and cancelled gRPC streams must preserve remaining response bytes or close deterministically (Task 3).
- Fresh Windows extraction from an unrelated working directory must load bundled modules and run relay mode without installed dependencies (Tasks 1 and 4).

## File Structure

- `src/WindowsPowerShellRc.Transport/diagnostics.proto`: session RPC and relay control/data messages.
- `src/WindowsPowerShellRc.Transport/DiagnosticSession.cs`: shared client-side diagnostic stream lifecycle and session headers.
- `src/WindowsPowerShellRc/ClientSessions.cs`: atomic RC admission, expiry, and connection logs.
- `src/WindowsPowerShellRc/SessionService.cs`: diagnostic session stream handling.
- `src/WindowsPowerShellRc/RelayOptions.cs`: validated relay/RC command modes.
- `src/WindowsPowerShellRc/RelayHost.cs`: TLS relay host and services.
- `src/WindowsPowerShellRc/RelayRegistry.cs`: owned listener leases, bounded tunnel lifecycle.
- `src/WindowsPowerShellRc/RelayAgent.cs`: RC outbound registration and per-socket bridges.
- `src/WindowsPowerShellRc/TunnelPump.cs`: bounded byte forwarding and stream validation.
- Existing Program/CLI/GrpcApi/ConnectionManager/project/publisher/tests/docs: integrate these components.

### Task 3: Relay registration, allocation, and bounded tunnels

**Interfaces:** `RelayOptions.Parse(string[] args)` validates relay subcommand. `RelayHost.Build(RelayOptions options, ServerIdentity identity)` creates host without an engine. `RelayAgent.RunAsync(ConnectionAddress relay, int localPort, Action<string,int> allocated, CancellationToken token)` owns the RC registration; cancellation closes all bridges. Relay Register duplex stream acknowledges public host/port and internal lease credential, receives heartbeats, and announces socket IDs. Tunnel duplex stream claims lease/socket once, then sends data/EOF frames.
